Lectura de este registro, de arriba abajo:

 * Los GET de ubicaciones responden 200 sin token: son rutas publicas.
 * El primer POST /api/auth/login responde 200 y entrega el JWT.
 * El segundo POST /api/auth/login responde 401: password incorrecto.
 * GET /api/users/profile sin cabecera responde 401.
 * GET /api/users/profile con 'Authorization: Bearer ...' responde 200.
 * GET /api/users/ con el token de admin responde 200.
 * GET /api/users/ con el token de juan_perez responde 403: el token
   es valido, pero su rol no es Administrador. Esa es la diferencia
   entre 401 y 403, y la razon de que la seguridad sea de dos capas.
 * PUT /api/users/profile responde 200: la edicion de perfil funciona.
 * PUT /api/users/2/roles responde 200: el cambio de rol funciona.
 * PUT /api/users/3/roles con el token de juan_perez responde 403.
